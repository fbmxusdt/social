# Session: 2026-06-25 — Minimal user-flow revamp + genealogy tree

## Summary
Stripped `fbmxsocial` from the full fbmxdao dApp down to the core member journey: a route-per-step
flow (Connect → Register → Activate → FBMX → Collect → Withdraw) plus a Genealogy explorer. The
headline feature is a **one-button Activate** that auto-runs `approve(USDT) → depositUSDT → activateRank`
as three sequenced wallet signatures with an anti-spam wait between deposit and activate. Production
build is clean.

## What Was Done
- **New route-per-step structure** (`App.jsx`): `/` Connect (wallet-connect landing + entry routing),
  `/register`, `/activate`, `/fbmx`, `/collect`, `/withdraw`, `/tree`. Catch-all → `/`.
- **One-button Activate** (`pages/Activate.jsx`): resumable state machine
  `idle→approving→depositing→waiting→activating→done`. Step derived from public reads
  (`usdtAllowanceRaw`, `walletBalanceRaw`, `hasActivated`) so it skips approve when allowance exists and
  resumes at activate after a reload ("Finish Activation"). Jump-level picker capped at 14; also handles
  post-activation sequential rank-ups. Inter-step `transactionCooldown` wait via timeout (not a stale read).
- **Shared shell** (`components/FlowLayout.jsx`): connect / wrong-network / not-registered gating, slim
  step nav, read-only `AccountSummary`; calls `useUserData()` once and passes it to pages via render-prop.
- **New components**: `AccountSummary`, `ConnectPrompt`, `WrongNetworkBanner`, `FbmxDepositPanel`
  (extracted from the old DepositPanel), `config/ranks.js` (single source for rank labels/colors).
- **Genealogy** (`pages/Tree.jsx` + reused `components/dashboard/GenealogyTree.jsx` from fbmxdao):
  Binary tree (binaries.left/rightAddress) + Affiliate referral tree (getChildren) with tab switch,
  depth 1–5, downline search, breadcrumb nav, re-rooting.
- **Navbar** trimmed to flow links; removed `ALL_TABS`/dashboard submenu/owner-admin logic.
- **Register nav hidden once registered** — filtered in both FlowLayout (uses `useUserData.isRegistered`)
  and Navbar (lightweight `isUser(address)` read).
- **useUserData**: added one field `user.walletBalanceRaw` (raw BigInt) for Activate's deposit detection.
- **contracts.js**: added `MAX_JUMP_LEVEL = 14` (contract `maxRank`; jump reverts above it).
- **Deleted** (user chose hard delete): pages Landing/Swap/Staking/Rewards/Loyalty/Admin/Dashboard;
  components BannerAds/UpgradePanel/TransactionHistory/MasterListPanel/DepositPanel; `lib/migration.js`.
- Updated project `CLAUDE.md` (data-flow, contract constraints, rank source, removed-features note).
- `npm ci` installed deps; `npm run build` passes (~6.4–6.7k modules, no errors).

## Key Contract Constraints (verified in contracts/fbmxdao_v2.sol)
- `register()` does **not** pull USDT (only checks balance ≥ entryFee) — no approval needed.
- `antiSpam` modifier: EOA-only (`msg.sender == tx.origin`) → **no multicall batching possible**;
  1 call/block; `transactionCooldown` (on-chain default **6s**) between calls.
- `pendingTargetLevel` is **private** → resume state derived from public reads instead.
- `maxRank = 14` (jump cap), though rank 15 (Emperor) reachable via sequential re-ups.
